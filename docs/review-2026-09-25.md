# 代码审查与 Beta 改造记录（2026-09-25）

## 一、Codex 已完成工作的审查

审查范围：提交 `b125c94` 到 `a339189` 的全部代码、文档与测试，本地执行 `pnpm typecheck`、`pnpm test`（22 项）与 `pnpm build`，全部通过。

### 做得好的部分

- **版本隔离**：v1–v4、v3.1、v3.2 的提示词分文件保存，引擎按版本拼接，旧版本不读取新研究资料；每次结果带提示词哈希与输入哈希，可复现。
- **证据约束**：模型输出必须通过 JSON Schema、引用校验（画像字段、市场信号 ID、研究 ID 必须真实存在）和评分/概率清洗；不通过最多修复一次，再失败就报错，不生成替代结果。
- **研究资料处理谨慎**：49 份问卷只接入经审核的描述性发现，Q25 因分母问题排除；六人访谈只保留匿名主题；不把群体比例转成个人概率。
- **隐私基线**：画像只在页面内存；服务端拒绝含邮箱/手机/身份证的输入与输出；错误信息不回显输入；模型密钥只在服务端；公开环境强制访问密钥。
- **诚实的文档**：没有真实模型输出就不写前后对比，release notes 明确标为“待输出验证”，没有编造结果。

### 发现的问题与建议

## 二、本次改造：把 Beta 测试加进每个版本

设计原则：真人参与、明确同意、按版本记录、默认匿名、可撤回。

### 新增

| 文件 | 作用 |
| --- | --- |
| `src/app/consent/page.tsx` | 中英文同意页；解析邀请链接参数 `v`（预选版本）、`k`（访问密钥）、`c`（分组） |
| `src/app/feedback/page.tsx` | 五个固定问题；只在同意且本次生成已记录时可提交；提交后可换版本再测 |
| `src/beta/contracts.ts` | 同意上下文、反馈、`run`/`feedback` 记录的 Zod 协议；同意文本版本号 |
| `src/beta/anonymize.ts` | 保存前去标识：邮箱、电话、证件号、链接、社交账号、自我介绍姓名、中英文机构名 |
| `src/beta/store.ts` | 可插拔存储：JSONL 文件、HTTPS webhook、二者同时 |
| `src/beta/record.ts` | 服务端写记录：生成结果由服务端直接记录，不接受浏览器回传的结果；反馈需匹配已有记录与参与者 |
| `src/app/api/beta/feedback/route.ts`、`src/app/api/beta/config/route.ts` | 反馈提交；公开的非敏感配置（记录是否开启、存储类型、可测版本） |
| `scripts/export-beta.ts` | 匿名 CSV + JSON 导出，按版本汇总 |
| `scripts/withdraw-beta.ts` | 凭参与者编号删除全部记录 |
| `scripts/mock-llm.mjs` | 本机假模型，只用于演练流程 |
| `tests/beta.test.ts` | 去标识规则、记录写入与关联、拒绝条件 |

### 修改

- `/api/recommend` 接受可选的 `beta` 同意上下文，成功生成后立即记录并在响应里返回 `beta.recordId` 与存储状态。
- 会话 Provider 增加同意状态、参与者编号、预选版本；这三项存在 `sessionStorage`（关标签页即清除），画像与结果仍只在内存。
- 画像页在未作出同意选择前先引导到 `/consent`；推荐页显示测试模式提示与记录状态；首页主按钮改为「参加测试」。
- v4 提示词与 manifest 中“Beta 已取消”的说法撤销；`/compare` 改名“版本对比（开发）”并移到导航末尾。
- `.env.example` 增加 `BETA_COLLECTION`、`BETA_STORAGE_DIR`、`BETA_WEBHOOK_URL`、`BETA_WEBHOOK_TOKEN`。

### 验证

- `pnpm typecheck`、`pnpm test`（25 项）、`pnpm build` 通过。
- 用假模型在无头浏览器里完整走了一遍：邀请链接 → 同意 → 填写含姓名、微信、公司名的画像 → 生成 v1 → 提交含公司名的反馈 → 同一画像改测 v3.2 → 导出。落盘记录与导出文件中姓名、微信、公司名均已替换为占位符；拒绝同意的会话没有产生任何记录，反馈页被拦截。
