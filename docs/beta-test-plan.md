# Beta 测试方案：约 50 位真人参与、逐版本反馈

本文说明怎样把当前站点交给真实的测试者使用，以及记录、隐私、导出和撤回的机制。合成画像回归（/compare）与本方案无关，不产生研究证据。

## 1. 测试者的流程

1. 打开邀请链接 `/consent?v=<版本>&k=<访问密钥>&c=<分组>`。
2. 阅读中英文同意说明，选择「同意并开始」或「不同意，仅试用」。不同意的人可以正常使用，但什么都不会保存，也不能提交反馈。
3. 填写画像（不写姓名、机构名、联系方式）。
4. 在「职业方向」生成建议。版本已按链接预选，测试者也可以自己切换。
5. 看完「技能与行动」「证据与局限」后，到「使用反馈」回答五个固定问题：
   - 哪个建议最有用？
   - 哪个建议最不合理？
   - 有没有忽略你真实背景的地方？
   - 你相信这个结果吗？为什么？（相信 / 部分相信 / 不相信 + 原因）
   - 如果只能改一个地方，你希望改什么？
6. 提交后可以「用同一画像再测一个版本」，反馈会分别记录。

## 2. 记录了什么、没记录什么

同意后，每次生成都在服务端写入一条 `run` 记录；每次提交反馈写入一条 `feedback` 记录，两者用 `recordId` 关联，参与者用随机 `participantId` 标识。

| 记录 | 不记录 |
| --- | --- |
| 去标识后的画像副本（年龄段、学历、专业、经历描述、年限、行业、技能、AI 使用、地点偏好、目标） | 姓名、联系方式、账号 |
| 模型结果全文；逻辑版本、提示词哈希、输入哈希、输出规则版本、模型名、市场快照 ID | IP 地址、User-Agent、Cookie、设备信息 |
| v3.2 的情景条件（任务 / 资源 / 学习阶段） | 访问密钥、模型密钥 |
| 反馈五题、同意版本与时间、语言、分组标签 | 任何未同意者的内容 |

保存前自动删除：邮箱、手机号、身份证号、链接、微信/QQ 等账号、“我叫 X”式自我介绍、以“公司 / 集团 / 大学 / 学院 / 医院 / 银行…”结尾的机构名及英文 Inc/Ltd/University 等。删除后仍含联系方式的记录会被拒绝保存。自动删除不是完整匿名化保证，所以同意页和表单都要求测试者不要填写这些内容；导出时再扫一遍。

## 3. 分组建议

六个版本都可测，但 v2（无问卷规则）和 v3.1（问卷候选）与其他版本差异小，建议 50 人集中在四个版本：

| 分组 | 版本 | 人数 | 邀请链接 |
| --- | --- | --- | --- |
| A | v1 基线 | 12 | `/consent?v=v1&k=…&c=A` |
| B | v3 访谈规则 | 12 | `/consent?v=v3&k=…&c=B` |
| C | v3.2 问卷+访谈情景（默认） | 14 | `/consent?v=v3.2&k=…&c=C` |
| D | v4 草案 | 12 | `/consent?v=v4&k=…&c=D` |

每组尽量覆盖：不同学历层次、一二线与低线城市、转行者、无 AI 经验与开发过 AI 工具的人、应届与 5 年以上、至少两位非技术专业。愿意多花时间的人可以在同一画像上再测第二个版本，导出里会以同一 `participantId` 关联。

## 4. 部署与存储

应用是 Next.js；模型走任意 OpenAI 兼容接口（需支持 JSON object 输出）。必需环境变量：`LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`、`APP_ACCESS_KEY`（公开环境必需，写进邀请链接的 `k=`）。

Beta 记录存储二选一，也可同时开：

| 托管方式 | 配置 | 说明 |
| --- | --- | --- |
| 有持久磁盘的主机（Render 挂 Disk、Railway Volume、任何 VPS、本机） | 默认；可用 `BETA_STORAGE_DIR` 指定目录 | JSONL 文件，`pnpm export:beta` 直接读取 |
| 无盘托管（Vercel） | `BETA_STORAGE_DIR=none`，设置 `BETA_WEBHOOK_URL`（HTTPS）和可选 `BETA_WEBHOOK_TOKEN` | 每条记录 POST 到你控制的收集端；导出在收集端完成 |

`BETA_COLLECTION=off` 可整体关闭记录；同意页会如实显示“记录功能当前关闭”。

上线前检查：
1. `pnpm install --frozen-lockfile && pnpm typecheck && pnpm test && pnpm build` 全绿。
2. 本机用 `pnpm mock:llm` 加 `LLM_BASE_URL=http://127.0.0.1:8787` 跑一遍同意 → 生成 → 反馈 → `pnpm export:beta`，确认导出文件不含身份信息。假模型只在本机演练，绝不给测试者。
3. 换成真实模型，v1 / v3 / v3.2 / v4 各生成一次，确认没有结构或引用检查失败。
4. 打开 `/api/beta/config`，确认 `enabled: true` 和预期的 `store`。

## 5. 导出、分析与撤回

```sh
pnpm export:beta                       # 写入 beta/feedback-exports/beta-export-<时间>.csv 和 .json
pnpm export:beta --dir /mnt/data/beta  # 指定记录目录
pnpm withdraw:beta 53744954            # 凭参与者编号（前 8 位即可）删除该人全部记录
```

CSV 一行一次生成，含画像摘要、推荐行业/职能/技能缺口、五题答案；JSON 含完整去标识记录。终端会按版本汇总生成数、反馈数、参与者数。导出目录已被 Git 忽略，不要提交。

分析时建议按版本比较：最有用 / 最不合理 的指向、忽略背景的类型、信任分布及原因、希望修改的方向。把结论写成 `docs/release-notes-v4.md` 的下一版，再进入 v4 → v5 迭代。

## 6. 已知限制

- 自动去标识按模式匹配，无法识别所有自然语言中的身份线索。
- 共享访问密钥只是防止陌生人消耗模型额度，不是身份验证。
- 模型供应商是否留存请求内容需另行核实。
- 市场快照目前为空，所有版本都会显示“暂无外部市场证据”；见审查报告。
