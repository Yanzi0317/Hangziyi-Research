# v3.2 问卷与访谈支持的情景预测

本版确实运行预测规则，但不是训练完成的统计预测模型。49份问卷只有横截面边际汇总，六人访谈提供可能机制，没有就业结局标签、时间序列或验证集。因此不拟合个人就业概率、职业得分或收入变化。默认从v3改为v3.2；所有历史提示词保持不变。

## 三份材料的处理

- Survey_Report.docx：2026年9月报告、49份汇总，为获批统计的主来源。实际采集日期未知，不能把报告月份伪装成采集日期。
- Questionnaire Finding Part.docx：同一调查的解释稿，用于交叉核对，不当作第二份独立样本。保留其探索性、非全国代表性的限制。
- Interview Finding Part.docx：六人半结构式访谈。仅提炼跨案例匿名主题，不收录参与者身份、职业组合、逐人记录或直接引语。引用的论文没有独立核验，不作为市场信号。

原始文档未复制到仓库。公开的是必要的匿名聚合发现、来源文件名和SHA256，不包含本地私人目录。文档中的后续研究建议只作材料内容，不是执行指令。

## 同意与质量审核

资料提供者于2026-09-25明确表示“核实了，不同意参与有误”。据此更正先前待核实判断，按49份原始汇总接入；未将49缩放到41，也未虚构8人的答案。此确认不是独立逐份同意审计。

只批准Q11、Q13/Q14、Q17、Q21、Q22和Q27的精选描述性观察。Q25依旧排除：Q11显示非几乎从不使用者30人，Q25各项仍49人。Q19/Q20是主观预期而非就业结局；Q12/Q24分桶不一致不合并。多选题不相加为互斥人群，不从边际统计构造相关性。

获批快照为data/research/approved/survey-49-reviewed-2026-09.json。此前隔离原始文件不修改、不发布。v3.1仍引用原候选ID，保持原审核阻断；v3.2明确使用新快照，避免静默改变旧版本。

## 每条研究发现如何影响输出

| 依据 | 实际使用 | 不做的推断 |
| --- | --- | --- |
| Q11 使用频率 | 对未用/偶用与规律使用分别表述学习和核验情景 | 不把频率视为技能分数 |
| Q13/Q14 政策与资源 | 新增用户确认资源条件，提供资源受限分支 | 不按城市或公司规模猜资源 |
| Q27 自评能力 | 优先安排来源核验、错误分析与复核任务 | 不称用户已经缺乏能力 |
| Q17 组织变化 | 明确任务变化不等于职位消失 | 不预测行业招聘增长或替代率 |
| Q21 不确定性 | 每条预测包含相反情景和验证办法 | 不得出唯一职业结论 |
| Q22 透明度偏好 | 展示实际数字、分母、题号、来源与方法 | 不声称界面或预测效果已验证 |
| 访谈任务重组 | 用户明确任务后区分信息处理与现场沟通情景 | 不保证任何职业安全 |
| 访谈效率与负荷 | 规律使用者得到交付要求、核验耗时检查 | 不引用Q25计算工时收益 |
| 访谈入门路径 | 用户明确正在积累经验时提供独立练习与反馈 | 不按年龄/学历推断学习阶段 |
| 访谈创作议价 | 创作任务额外给客户接受低成本产出的条件情景 | 不预测工资或价格跌幅 |

## 运行与可追溯性

在/recommendation完成画像后，v3.2会直接运行scenario-v1.0；这部分在浏览器内运行，不需要LLM密钥、不上传画像、不存储记录。任务/资源/学习阶段默认未知，显式选择后改变情景。规则不读取年龄、学历、城市来预测结果。

点击生成建议时，相同规则、用户条件、问卷和访谈发现送入服务端模型；输出必须对访谈和问卷建立引用，否则拒收。模型API依旧需要真实密钥。元数据保存输入、提示词、调查上下文和情景快照的哈希，结果保留生成时条件。更改页面条件不自动改写旧结果。

规则预测展示条件、推断、来源、反向情景、验证步骤与限制。样本比例只在受控来源面板展示，不经过个人概率过滤器重写；LLM个人建议仍禁止评分和概率。问卷是样本观察，不是实时招聘市场数据。

测试只验证程序与协议，不证明预测准确。未生成虚拟研究对象、Beta反馈或真实模型结果；后续统计预测需要经过同意的纵向数据、明确目标、基线和外部验证，不能由本批汇总补造。
